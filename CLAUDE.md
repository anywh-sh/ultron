# ultron

Wrapper multiplataforma para o Claude Code CLI (máquina Debian headless central, acesso via SSH/Tailscale).

MVP funcional completo e validado (chat, dois perfis, multi-sessão, voz, imagem). Cliente migrado de TS vanilla pra **React + TypeScript + Tailwind CSS + shadcn/ui** sobre Tauri 2.0 — migração completa em 8 fases, todas validadas no Windows real. Relay ganhou persistência de sessão em disco (sobrevive a restart). Barra de título customizada implementada e validada no Windows ([`docs/21`](./docs/21-titlebar-customizada-plano.md)): chrome nativo removido, botões próprios, Back/Forward, busca de sessão (Ctrl/Cmd+K), toggle de sidebar unificado. Ícone final do app (`>` + cursor) exportado e aplicado pros dois SOs. Primeiro teste real no macOS feito (2026-08-21): app rodando, `.dmg` de instalação (arrastar-pra-Applications) validado com assinatura ad-hoc — ver `docs/20-backlog.md` pros detalhes e pro que ainda falta lá (download automático do modelo Whisper) e no instalador do Windows (não iniciado).

**Frente ativa: port iOS.** Phase 0 de investigação concluída ([`docs/22`](./docs/22-mobile-ios-investigacao.md), 3 spikes validados: toolchain, UI nativa Liquid Glass via plugin Swift, reconexão em background). Plano de implementação ([`docs/23`](./docs/23-mobile-ios-plano-implementacao.md)) com as Fases A-E **todas concluídas**: fundação do projeto iOS, gating de voz/titlebar/tabs, Photo Picker nativo validado, reconexão com backoff (`RelayClient`), e o plugin `tauri-plugin-native-chrome` promovido com um comando real de indicador de conexão. **Só falta a Fase F (distribuição)** — depende de uma decisão do usuário (conta Apple Developer paga, $99/ano) antes de configurar signing/TestFlight; sem essa conta, o app já é totalmente iterável no Simulator. Não precisa reler `docs/00` a `docs/22` pra continuar — `docs/23` tem tudo. **Antes de mexer em qualquer coisa relacionada ao Simulator/Mac remoto, ler [`docs/38`](./docs/38-guia-teste-simulador-ios.md)** — playbook consolidado (checklist, comandos prontos: build/install, automação de toque via `agent-device`, seed de sessão via `localStorage`, captura de log do simulador) mantido atualizado pra isso, não repetir a investigação do zero a cada sessão; `docs/31` tem o histórico sessão a sessão por trás dele, só consultar se precisar do "porquê". Rodada de polish pós-MVP em andamento (bugs/melhorias reportados pelo usuário usando o app de verdade) rastreada em [`docs/34`](./docs/34-qa-melhorias-ios.md) — lista viva de casos de teste, cada um com causa raiz e fix aplicado, pendente de validação no Simulator/device assim que o Mac estiver acessível. Investigação de notificações melhoradas (background/killed app, Apple Watch, turno concluído em outro dispositivo) em [`docs/35`](./docs/35-notificacoes-push-investigacao.md) — achado central: push de verdade exige conta Apple Developer paga, bloqueio duro da Apple sem workaround técnico. Usuário decidiu remover o item de multi-dispositivo do escopo; spike real no Simulator (Mac acessível de novo) em [`docs/36`](./docs/36-notificacoes-spike-background.md) confirmou que nem o caso "app minimizado" funciona hoje — o WebKit suspende o processo do JS em ~1.2s ao entrar em background, antes de qualquer mensagem assíncrona ter chance de chegar. Recomendação registrada: não vale perseguir mais nenhum dos 3 pedidos sem a conta paga. Fix aplicado pro caso restante que o usuário pediu pra garantir (nunca notificar olhando a própria sessão) em [`docs/37`](./docs/37-notificacao-foco-real-fix.md) — `useWindowFocus.ts` trocou a API de foco de janela do Tauri por `document.visibilityState` no iOS, já que a primeira dispara falso positivo em qualquer interrupção momentânea (Control Center, alerta do sistema), não só background real.

O backlog do desktop ([`docs/20-backlog.md`](./docs/20-backlog.md) — instalador de um clique, waveform de voz, destacar aba em janela própria) continua válido mas não é a prioridade da sessão atual.

Toda a documentação (histórico de decisão completo) vive em [`/docs`](./docs), em ordem numérica, começando por [`docs/00-premissa.md`](./docs/00-premissa.md).

## Workflow de contribuição

Detalhes/justificativa em [`docs/24-preferencias-contribuicao.md`](./docs/24-preferencias-contribuicao.md).

- Commits separados por responsabilidade (atômicos) — nunca misturar mudanças de propósitos diferentes num único commit, mesmo que tenham sido feitas na mesma sessão. Se o working tree acumulou mais de uma feature/fix, separa em commits distintos (stage seletivo por arquivo/hunk) em vez de um commit único.
- Sempre seguir [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `refactor:`, `style:`, `docs:` etc., com escopo quando fizer sentido, ex. `feat(client): ...`).
- **Texto do commit (título + corpo) sempre em inglês**, mesmo com o resto da conversa em português.
- Ao terminar um trabalho (bug corrigido, feature implementada, o que foi pedido na sessão), o passo de conclusão inclui commitar (nos moldes acima) e dar `git push` pro repo remoto — isso faz parte de "terminar a tarefa", não é uma ação extra que precisa ser pedida à parte toda vez.
