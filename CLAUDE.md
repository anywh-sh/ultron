# ultron

Wrapper multiplataforma para o Claude Code CLI (máquina Debian headless central, acesso via SSH/Tailscale).

MVP funcional completo e validado (chat, dois perfis, multi-sessão, voz, imagem). Cliente migrado de TS vanilla pra **React + TypeScript + Tailwind CSS + shadcn/ui** sobre Tauri 2.0 — migração completa em 8 fases, todas validadas no Windows real. Relay ganhou persistência de sessão em disco (sobrevive a restart). Barra de título customizada implementada e validada no Windows ([`docs/21`](./docs/21-titlebar-customizada-plano.md)): chrome nativo removido, botões próprios, Back/Forward, busca de sessão (Ctrl/Cmd+K), toggle de sidebar unificado. Ícone final do app (`>` + cursor) exportado e aplicado pros dois SOs; no Windows a nitidez do ícone na taskbar precisou de um fix próprio (o Tauri instala na janela só a primeira entrada do `.ico`, de 16px) — causa raiz, evidências e o que não vale mexer em [`docs/40`](./docs/40-icone-windows-nitidez-causa-raiz.md). Primeiro teste real no macOS feito (2026-08-21): app rodando, `.dmg` de instalação (arrastar-pra-Applications) validado com assinatura ad-hoc — ver `docs/20-backlog.md` pros detalhes e pro que ainda falta lá (download automático do modelo Whisper) e no instalador do Windows (não iniciado).

**Frente ativa: abertura do código (open source) e, na sequência, a infra paga.** Estratégia de monetização, arquitetura da infra paga e framework de precificação em [`docs/42`](./docs/42-monetizacao-e-open-source-plano.md) — decisão central: o Ultron vende infra (execução hospedada + conectividade gerenciada), não a ferramenta; cliente/relay ficam open source. A auditoria de prontidão pra abrir o código e o plano que saiu dela estão em [`docs/44`](./docs/44-open-source-readiness-plano.md), **já executado por completo** (o repo está pronto pra publicar) — leia esse doc antes de mexer em qualquer coisa de open-source readiness, ele registra o que já foi feito, o que ficou de fora de propósito e, principalmente, **as decisões de produto que não devem ser reabertas** (o relay não ter autenticação é intencional; a config de conexão do cliente é build-time por env var, não tela no app). O que resta do `docs/42` é o item 5 (infra paga: API de controle, sandbox de execução, vault de segredo), cujo bloqueador é verificar o ToS da Anthropic sobre execução hospedada com token de assinatura de terceiro.

**Frente anterior (concluída): port iOS.** Phase 0 de investigação concluída ([`docs/22`](./docs/22-mobile-ios-investigacao.md), 3 spikes validados: toolchain, UI nativa Liquid Glass via plugin Swift, reconexão em background). Plano de implementação ([`docs/23`](./docs/23-mobile-ios-plano-implementacao.md)) com as Fases A-E **todas concluídas**: fundação do projeto iOS, gating de voz/titlebar/tabs, Photo Picker nativo validado, reconexão com backoff (`RelayClient`), e o plugin `tauri-plugin-native-chrome` promovido com um comando real de indicador de conexão. **Só falta a Fase F (distribuição)** — depende de uma decisão do usuário (conta Apple Developer paga, $99/ano) antes de configurar signing/TestFlight; sem essa conta, o app já é totalmente iterável no Simulator. Não precisa reler `docs/00` a `docs/22` pra continuar — `docs/23` tem tudo. **Antes de mexer em qualquer coisa relacionada ao Simulator/Mac remoto, ler [`docs/38`](./docs/38-guia-teste-simulador-ios.md)** — playbook consolidado (checklist, comandos prontos: build/install, automação de toque via `agent-device`, seed de sessão via `localStorage`, captura de log do simulador) mantido atualizado pra isso, não repetir a investigação do zero a cada sessão; `docs/31` tem o histórico sessão a sessão por trás dele, só consultar se precisar do "porquê". Rodada de polish pós-MVP em andamento (bugs/melhorias reportados pelo usuário usando o app de verdade) rastreada em [`docs/34`](./docs/34-qa-melhorias-ios.md) — lista viva de casos de teste, cada um com causa raiz e fix aplicado, pendente de validação no Simulator/device assim que o Mac estiver acessível. Investigação de notificações melhoradas (background/killed app, Apple Watch, turno concluído em outro dispositivo) em [`docs/35`](./docs/35-notificacoes-push-investigacao.md) — achado central: push de verdade exige conta Apple Developer paga, bloqueio duro da Apple sem workaround técnico. Usuário decidiu remover o item de multi-dispositivo do escopo; spike real no Simulator (Mac acessível de novo) em [`docs/36`](./docs/36-notificacoes-spike-background.md) confirmou que nem o caso "app minimizado" funciona hoje — o WebKit suspende o processo do JS em ~1.2s ao entrar em background, antes de qualquer mensagem assíncrona ter chance de chegar. Recomendação registrada: não vale perseguir mais nenhum dos 3 pedidos sem a conta paga. Fix aplicado pro caso restante que o usuário pediu pra garantir (nunca notificar olhando a própria sessão) em [`docs/37`](./docs/37-notificacao-foco-real-fix.md) — `useWindowFocus.ts` trocou a API de foco de janela do Tauri por `document.visibilityState` no iOS, já que a primeira dispara falso positivo em qualquer interrupção momentânea (Control Center, alerta do sistema), não só background real. Item 1 (`docs/34`) reabriu: fix do gap do teclado validado no Simulator mas reproduziu de novo no device físico real do usuário — Simulator não é suficiente pra validar esse item específico, ver [`docs/39`](./docs/39-gap-teclado-device-fisico-investigacao.md) pra hipótese (padding decidindo "teclado aberto?" a partir do cálculo errado) e o overlay de diagnóstico temporário adicionado pra confirmar no próximo teste real.

**Painel de arquivos do work directory (desktop): implementado e validado pelo usuário no app real (2026-09-06).** [`docs/41`](./docs/41-painel-arquivos-plano-implementacao.md) — visualizador read-only da pasta da sessão (árvore lazy, syntax highlight, `.md` formatado, preview de imagem, watch de arquivo ao vivo), empilhado no mesmo dock direito do terminal via botão próprio + `Ctrl+Shift+E`. `useSessionPanels.ts` (um slot só, trocando `kind`) foi substituído por `useSessionDock.ts`, um dock de até dois panes empilhados — terminal e arquivos agora coexistem. Watch de arquivo roda **só na forma não-recursiva** (um watcher por diretório/arquivo visível, nunca recursivo — não escala em repo com `node_modules`, medições em `docs/41`). Pendente apenas validar a atualização ao vivo (watch) numa sessão futura. **Armadilha real encontrada ao validar**: os serviços systemd do relay (`ultron-relay-*.service`) rodam `dist/server.js` compilado, não `src/` — reiniciar o serviço sozinho não pega mudança de código, precisa `npm run build` no `relay/` antes (o relay não tem watch/hot-reload em produção).

O backlog do desktop ([`docs/20-backlog.md`](./docs/20-backlog.md) — instalador de um clique, waveform de voz, destacar aba em janela própria) continua válido mas não é a prioridade da sessão atual.

## Idioma

O projeto está indo pra open-source, então tudo que não for texto de UI precisa estar em inglês, mesmo quando a conversa com o agente for em português:

- **Sempre em inglês**: comentário de código (`//`, `/* */`, doc comments), mensagem de commit (título + corpo), `console.log`/`console.error`/logs de servidor, e qualquer string que exista só pro desenvolvedor (nunca chega a ser renderizada pro usuário final).
- **Continua em português por enquanto**: qualquer string que é de fato mostrada na UI (texto JSX, `placeholder`/`title`/`aria-label`, `window.alert`/`window.confirm`, toast, mensagem de erro que chega até o usuário). Isso é intencional — o projeto não tem sistema de i18n ainda, então traduzir texto de UI hoje só criaria uma mistura pior. Antes de decidir se uma string é "UI" ou "não-UI", rastreia onde ela é consumida (ex.: um erro que sobe até um `alert`/toast é UI; um `console.error` não é) — não decide só por "parece uma frase".
- `/docs` e este `CLAUDE.md` continuam em português por ora — são o histórico de decisão do projeto, e traduzir isso é escopo de uma reorganização futura combinada com o usuário, não uma tradução solta.
- Contexto: o projeto foi construído em conversas em português sem essa diretriz explícita, e acumulou texto em PT em código e commits. Corrigido retroativamente em 2026-09 (histórico de commit reescrito via `git filter-repo`, comentários/logs traduzidos) — esta seção existe pra isso não voltar a acontecer.

## Workflow de contribuição

Detalhes/justificativa em [`docs/24-preferencias-contribuicao.md`](./docs/24-preferencias-contribuicao.md).

- Commits separados por responsabilidade (atômicos) — nunca misturar mudanças de propósitos diferentes num único commit, mesmo que tenham sido feitas na mesma sessão. Se o working tree acumulou mais de uma feature/fix, separa em commits distintos (stage seletivo por arquivo/hunk) em vez de um commit único.
- Sempre seguir [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `refactor:`, `style:`, `docs:` etc., com escopo quando fizer sentido, ex. `feat(client): ...`).
- **Texto do commit (título + corpo) sempre em inglês**, mesmo com o resto da conversa em português — ver seção "Idioma" acima.
- Ao terminar um trabalho (bug corrigido, feature implementada, o que foi pedido na sessão), o passo de conclusão inclui commitar (nos moldes acima) e dar `git push` pro repo remoto — isso faz parte de "terminar a tarefa", não é uma ação extra que precisa ser pedida à parte toda vez.
